# Codex production companion — review version

Read the current Transaction Operations Runbook and task-relevant Manual, Source Map, AI Execution Runbook and applicable lifecycle/Click/FUB instructions through their registered IDs. Current Drive content controls business meaning. This source is a bounded artifact tool, not a new SOP, CRM, task database or Operations Bus.

## 1. Bind the request and locate the originals

Everyday entry: the exact client's transaction Workbench under **Blaise RE — Sellers & Transactions**. Resolve client identity, represented side, exact property and all contracting parties from that context; a generic request is allowed only with those explicit Workbench bindings. Work retains the business context; Codex handles production. Direct Codex is also supported.

Retrieve the complete executed package or unchanged original export from Drive or another supported original source. No mandatory vendor/provider hop. Keep originals unchanged in the existing offer-stage property/transaction folder under the client lifetime structure. Do not make a parallel transaction folder or source database. Keep private analysis and financial support separate from recipient-ready records. Missing access holds only dependent work.

Review all pages: agreement, incorporated addenda, counters, amendments and execution/acceptance/delivery evidence. Record required parties, signatures, initials, dates, final acceptance and amendment coverage. “Sent,” “delivered,” “completed,” an open PDF, a filename or a text extraction is not proof that all parties executed the controlling terms. Inspect the actual original image/signature fields; resolve any legal effect question with Blaise/broker/counsel. Never draft new legal clauses here.

When machine reading is unavailable, use explicit original-source human verification with verifier name/role/time, original locator and version, page count, covered page/section, operative quoted terms, signature/initial/date/completion status, acceptance/delivery anchor and amendment coverage. A paraphrased email or unverified summary is **reported**, not human-verified. Keep unverified terms unknown; continue useful routing, file organization and verification drafts.

## 2. Prepare evidence-bound interpretation outside the repository

Create `case.json`, the exact `request.txt`, and `analysis.json` in a private task-local directory. `fixture_pack.fixture` illustrates the schema; it is not a generic contract parser. Never copy its property, dates, providers, obligations or dollar amounts into a live case. Set `mode` explicitly; synthetic originals are rejected in live mode.

Case: exact client/property/parties, side, explicit-offset review time, America/Chicago timezone, original source IDs/versions/locators/files, actual people and assignment evidence, existing folder locations and only the relevant bounded CRM snapshot. Keep proposed and unknown providers separate from actual assignments. No Laura/TitleSmart or other provider default. Client choice remains with the client. Include TC economics only when a current assignment decision needs it; omit private economics from recipient drafts.

Analysis: bind the exact request hash; identify the base agreement and each amendment/attachment separately. Attribute the reviewer and reviewed pages to the actual file hash. Each completion assertion needs the supporting original citation. Each obligation includes the contractual responsible party, operational owner with assigned/proposed/unknown state, next action, amount if applicable, exact operative quote and deadline rule. Check owner claims against the cited terms and verified assignment context. Do not equate the agent's typed boolean with signature verification.

Extract **every applicable actual obligation**, not a universal checklist: earnest money, inspection and response, financing/written statement, appraisal, association/CIC review, title, closing, possession and any property-specific provision. Exclude inapplicable categories. Keep missed, ambiguous or absent terms visible. Source-read, Human-verified, Reported, Derived and Unknown are distinct. Exact quoted text is stored privately; human views show concise source references. Unknown amount is null, never zero.

Deadlines require a source-stated date or an explicitly supported anchor, day count, calendar/business unit, trigger-date inclusion and time/timezone. Use `date_text`, `time_text`, `days_text` when the source's wording differs from normalized values. No default statutory period, midnight, holiday calendar or weekend rolling. Business-day calculation requires explicit weekdays and holiday dates plus their controlling support. Ambiguous legal counting/rolling remains unknown; do not select a convenient rule. The tool rejects unsupported adjustments and ambiguous/nonexistent local times. Date known/time unknown remains a date with a missing-time hold. Show derived arithmetic and controlling source in provenance.

## 3. Reconcile updates; preserve ownership

Keep originals and the complete amendment chain in each run. An executed replacement specifies its predecessor; only the affected obligation changes. Drafts and reported dates never displace signed controlling terms. Preserve original booking or event records where relevant; reported completion is not verified receipt. Match update evidence to the property, source owner, actual occurrence time and source type. A verified specialist receipt/completion/delegation suppresses duplicate Blaise work; “sent” alone does not mean received or completed.

Pass the previous generated provenance for a readable before/after. Stable IDs bind the same obligation. Disappearing prior obligations are rejected; explicit termination, waivers or disputed legal effects need source review and a supported reconciliation, not deletion to bypass a check. If a change introduces a new valid obligation, label it as new and show its evidence. Existing obligations remain.

Select Blaise's immediate recommendation with a supported reason. The engine does not invent transaction strategy. Keep ownership with the actually assigned TC/lender/title/party. Create a Blaise task proposal only for a real personal commitment; this v1 emits no automatic tasks. Minimal field/note proposals route through the existing `lead-conversion-crm`, with exact-target and fresh duplicate checks at the time of a separately authorized write. Repeated generation itself makes zero business-system changes.

## 4. Generate, inspect and return

Use `engine.py`, then `render.cjs`. Each run writes a new directory; inspect the print PDF page by page and the genuinely reflowed phone version. Review hierarchy, dates, amounts, source states, owner language, missing evidence, clipping and footer contact. The shared renderer loads local assets only. Do not reduce body text to force a page count; add pages as needed.

Read each recipient draft separately: exact recipient/routing, useful scope, no confidential strategy, compensation or support details. The generator shares only allowlisted obligation labels/dates, not raw private next-actions or provenance. The operator may refine a draft against current business context before normal send review, but must not smuggle private analysis into it. Draft generation is not sending. Missing recipient/assignment holds only that handoff. Select only appropriate original attachments after review.

Calendar output is an advisory with title, date/time/timezone, client/property, owner/source and missing fields. No event was created. Every sample says **SYNTHETIC — DO NOT ADD TO CALENDAR**. No live record, contract, send, signature, Calendar, schedule, monitor, payment or spending action belongs to this build.

Return the private brief and review drafts with exact generation/readback status. File through the existing canonical/transaction structure, preserving stable IDs for updated durable files. This review package is fictional and private. Governing additions remain proposed; no PR merge without the approved process. Testing this artifact companion is not a new gate on ordinary buyer/seller work or a claim of live end-to-end capability.

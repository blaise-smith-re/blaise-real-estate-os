# Codex invocation contract
Trigger: **Prepare my open house for [ADDRESS], MLS [MLS]. Listing agent: [NAME]. Proposed date/time: [YYYY-MM-DD, START–END America/Chicago]. Use production/open-house.**

This is an agent-operated workflow, not a requirement that Blaise run Python or fill JSON. Continue safe preparation until the package is reviewable. Do not ask for facts or image choices that can be retrieved. Resume an existing case; never restart or duplicate it.

1. Run `engine.py init` with the trigger fields and a private case directory outside the repository. Default timezone America/Chicago; ask only if an essential fact cannot be resolved. Do not infer event confirmation.
2. Retrieve current Source Map through the connected Drive tool. Confirm exact active IDs for the five owners in governance.json; retrieve those current sources. Reject legacy/retired/superseded/archived titles/status before opening. Record ID/title/status/retrieved_at/content_sha256 in case.governance_receipt. Do not copy historical governance into production context. If an active ID changed, update the locator cache through a reviewed source-control change.
3. Use the current authenticated Matrix tab through the supported browser operator. Confirm account/property/MLS identity, exact price and search criteria; inspect the host-level facts specified in the playbook. Save only useful source reports/documents. Fill retrieved case fields from observed evidence, not guesses. No Add/Edit, sends, portal, guessed API, cookie extraction or credential/session reuse. Login/MFA is a genuine possible Blaise step. Resume after it.
4. Open Photos and retrieve the usable large site-supported renditions through the browser's supported download/export path. Read only the currently displayed page/DOM. Save exact observed source URLs/sequence IDs alongside the untouched downloaded files. Do not synthesize higher-size URLs. `media.py ingest` copies these files into case originals with hashes and generates a contact sheet. A failed image fetch should retry through the supported viewer/download; never substitute a low-quality screenshot silently.
5. Visually inspect the contact sheet and selected full images. Codex classifies useful candidates by roles (exterior/kitchen/living/suite/outdoor/detail/secondary), rejects duplicate/watermarked/irrelevant media, scores role fit and records focal position. This is visual model judgment; the local engine does not pretend to recognize room types. Save roles/fit/excluded fields in media candidates. The engine performs selection and crops without requiring Blaise to choose photographs. Missing room imagery can use another actual property view only with truthful copy.
6. Resolve the current approved portrait library by canonical brand pointers. Review headshots and professional portraits, excluding archive/unsorted files. Retrieve appropriate approved candidates; record ID, source_url, local file, hash, approved status and role-fit scores for handout/social_06/social_08. Seed recent_ids from the last released campaigns' portrait-usage records (draft use is identifiable separately). Never treat the bundled four starter portraits as the entire library or sole choice. The engine avoids repeated IDs and penalizes recent use.
7. Research the actual address and surrounding roads in maps/browser. Select five nonredundant decision points on connected approaches, record approach orientation, actual turn arrow, rationale, placement order, source/time and on-site issues. Populate sign_route.stops; never copy a prior property's intersections. Route validation checks structure, not map truth. Inspect the route visually before marking research complete.
8. Build the concise six-section Host Brief, benefit-led marketing and practical 3–5 active alternatives. Derive copy from verified features. Facts/cautions go to separate inputs. HOA yes/no/unknown must be reconciled; unknown blocks the handout, not independent research. Prepare all safe drafts while release authority is pending.
9. Run `engine.py build --input CASE/case.json --out FRESH_RUN --node BUNDLED_NODE`. Inspect QA.json and actual two PDF previews, social images and phone brief. Fix clipping/copy within approved layout. Optional `contact_sheet.py RUN` creates a review board only if useful. No optional board is a release asset.
10. Create the prepared durable filing package/manifest. Work/Blaise reviews business meaning and exact release. Do not upload, publish, send, schedule, create external events or change MLS/FUB from this invocation. Mark precisely what was prepared versus performed. Post-event facts and CRM effects require actual event evidence and the applicable later authority.

The repository engine automates deterministic production after the agent gathers evidence. It is manually invoked and supervised; it is not a background service, crawler, autonomous MLS integration or deployed Operations Bus.
